IMPLEMENTED / VERIFIED APPROACH
Paper's inspected CraftServer.createWorld constructs new WorldOptions from
WorldCreator.seed only for a new world; existing level.dat supplies saved options.
Observed Paper Nether storage: <world>/DIM-1 with level.dat/uid.dat at world root.
The implementation uses a separate owned polder_nether world, environment NETHER,
with WorldCreator.seed and generated structures enabled. It preserves the existing
primary Nether and routes player/entity Nether portals to the managed dimension.
The Overworld and End are excluded by exact path, environment/layout and identity
checks. No claim is made that YAML edits regenerate an existing primary dimension.

FEATURES
- Default interval 120 real-world hours, last success/next deadline, pause state,
  maintenance phases, operation UUID, warning receipts and history in independent
  versioned nether-reset.db. Concurrent/stale/duplicate requests are rejected.
- Warnings at 30/10/5/1 minutes and 10 seconds. Access closes before evacuation;
  failed/cancelled teleports or unsafe Overworld destination block shutdown.
  Players/worlds save; the module never unloads/deletes a live world. Saved Nether
  login positions redirect to safe Overworld to avoid stale regenerated terrain.
- Separate offline Java maintenance worker with Windows PowerShell wrappers.
  Checks PID/start identity, world session locks, plugin maintenance interlock,
  canonical paths, links/reparse aliases, immutable markers and DIM-1 layout.
- Full directory copy, file-size/SHA-256 manifest verification, then atomic move
  of original world into timestamp/UUID backup. New world is generated only on
  restart through the approved SHA-pinned Java/Paper launcher.
- Runtime API seed and read-only saved NBT seed checks plus changed generated
  block/biome fingerprints gate access reopening and successful outcome recording.
- Explicit shutdown opt-in AND current supervisor PID/token/start proof AND a
  successful supervised reset/restart rehearsal are required. No taskkill,
  Stop-Process, forced Java termination or guessed launcher command is used.
- Explicit operation-ID recovery, quarantined incomplete generations, restored
  old seed verification and paused schedule after rollback. Default retains three
  successful valid backups; newest valid recovery is never pruned. Incomplete
  backups remain for operator inspection; offline pruning may temporarily lag.

  fixture sources and Linux/Windows build/maintenance workflow.
